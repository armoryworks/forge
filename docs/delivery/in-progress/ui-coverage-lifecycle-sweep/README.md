# UI coverage + lifecycle sweep (ultracode plan)

Status: PLAN, not started. Written 2026-10-15 after a design partner reported a
clipped job dialog that none of the existing audits exercised.

## Why

The existing audits (`e2e/tests/ux-audit.spec.ts`, `e2e/tests/dialog-audit.spec.ts`,
`e2e/vision-sweep.mjs`) never opened an existing job's detail dialog, ran only at
desktop viewports of 1280x800 and larger, and assert on horizontal overflow only.
The one job-dialog test opens New Job. Coverage was a feeling, not a number.

Goal: every user interface Forge has (routed page, tab, dialog, mobile, worker,
kiosk, portal) is exercised with realistic data, at several viewports, by the
role that actually uses it, with machine checks for clean and usable, and the
coverage figure is computed against an inventory generated from source so it
can be held at 100% in CI.

## Definitions

- **UI state**: a (route, tab, dialog) triple reached by a driver. Routes come
  from the router config, tabs from `mat-tab-group` / `role="tab"` in templates,
  dialogs from every `.open(` call site (46 dialog components via `MatDialog`,
  18 detail dialogs via `DetailDialogService`, which also opens by
  `?detail=type:id`).
- **Clean**: no console errors, no failed HTTP, no raw i18n keys, no empty
  buttons, no element clipped by an `overflow: hidden` ancestor without a
  scrollable region in between, no horizontal page overflow, no interactive
  control off-viewport, tap targets at least 24px on the phone viewport.
- **Coverage**: states exercised / states in inventory, reported per surface.

## Phases (one ultracode workflow each, review between)

### 0. Prerequisites (no agents)
- Dev server reachable from other devices: `ng serve --host 0.0.0.0 --port 4300`
  with an `e2e` environment whose `apiUrl` is `/api/v1` and `hubUrl` `/hubs`, and a
  proxy to `localhost:5000`. The default `environment.ts` points at
  `http://localhost:5000`, which the laptop and phone cannot reach.
- API `FrontendBaseUrl` set to the dev-server origin for links in emails/PDFs.
- Fresh database from seed (`e2e/scenarios/reset-db.sh`) in a second compose
  project, leaving the 1270-job local stack intact.
- Laptop online on the tailnet; `npx playwright install chromium` under the
  user, headed Chromium launched with `--remote-debugging-port` bound to the
  tailnet address; the PC drives it with `connectOverCDP`.
- Phone (Pixel 10 Pro XL, GrapheneOS) on USB with debugging allowed;
  platform-tools in the scratchpad; `adb forward tcp:9222
  localabstract:chrome_devtools_remote`; `connectOverCDP` to Vanadium. Fallback:
  the worker role is played by hand on the phone and evidence is
  `adb exec-out screencap`.

### 1. Inventory (about 8 agents)
Parallel readers, one per group of route files (55 files, about 178 paths),
emit a route table: full path, params and the API list endpoint that supplies a
real id, guards and capabilities, surface (desktop, mobile `/m`, mobile-app
`/app`, worker, kiosk `/display/shop-floor`, portal, dev-tools). Two more agents
produce the dialog inventory (component, opener component, opener method,
template trigger, whether a detail-param open exists) and the tab inventory.
One adversarial agent recounts from a clean grep and diffs. Output:
`e2e/ui-coverage/inventory.json`, regenerated by script thereafter so the
inventory cannot drift from source.

### 2. Harness (one agent or inline)
`e2e/ui-coverage/sweep.mjs`: logs in per role via API, walks the inventory,
drives each state at 1920x1080, 1366x768, 1280x720, 1024x768 and 390x844 (mobile
surfaces at the phone viewport only), runs the checks above, screenshots each
state, writes `report.json` plus a markdown summary with coverage per surface
and findings ranked by severity. Driver kinds: route, tab click, detail param,
trigger click (create dialogs only, dismissed with Escape, never submitted).
States with no driver are reported as uncovered, not skipped silently.

### 3. Lifecycle scenario (about 13 agents, one per stage)
Reuse the lead-to-ledger role plan
(`docs/delivery/in-progress/lead-to-ledger-role-test-plan/`) and the stress
workflows (`e2e/stress/workflows/`). Each agent writes one stage as a Playwright
module using `e2e/lib`, ending with a sweep hook so screens are audited in a
realistic data state, not on an empty seed:

| Stage | Role | Device |
|---|---|---|
| Lead intake, lost lead, won lead | PM `pmorris@` | PC |
| Convert lead to customer, customer setup | Office `cthompson@` | laptop (headed, watched) |
| Parts, BOM, routing, cost roll, vendors | Engineer `akim@` | PC |
| Estimate, quote, send, accept | PM, Office | PC, laptop |
| Sales order, confirm, PO for material | Office, Procurement `buyer@` | laptop, PC |
| Shop floor: clock in, operations, timers, material issue | Worker `bkelly@` | phone (`/m`, kiosk) |
| Manager approvals, reassign, cancel | Manager `lwilson@` | laptop |
| Close production cost, ship, invoice, cash | Controller, Office | PC, laptop |
| Period close, admin settings, capability toggles | Controller, Admin | PC |

The sequence is leads, lost leads, customers, estimates, quotes, sales orders,
vendors, parts first, as requested, then production through to the ledger.
An adversarial agent per stage checks the script against the API contract
before anything runs.

### 4. Run and triage (about 6 agents)
Run the lifecycle with the sweep hooks on all three devices. Agents dedupe and
classify findings (clipping, overflow, accessibility, error, data, copy), then
each finding is reproduced by a verifier against the dev server with a
screenshot before it is accepted. Output: ranked finding list in this folder.

### 5. Fix (pipeline, one agent per finding, worktree isolation)
Fix, run eslint and `lint:standards` and the affected spec, re-run the specific
sweep state, return a patch. Patches are reviewed and pushed by the main
session only. Release as beta.31 once the sweep is at 100% with zero findings.

### 6. Ratchet
Nightly CI job runs the sweep against a seeded stack. Inventory is regenerated
from source each run, so a new route, tab or dialog without a driver fails the
build. Findings baseline starts at zero and stays there.

## Agent budget
Phases 1, 3 and 4 exceed the 10-agent session guideline. Either raise the
guideline for this effort or run phase 3 in two rounds. Phases 2 and 5 are
sized by the work found.

## Open points
- The earlier multi-device "NOM scenario" this mirrors is not recorded in memory
  or docs. The shape above is inferred: real devices, real roles, scripted
  automation with the owner playing some roles by hand.
- Laptop: needs ssh reachable over the tailnet and a logged-in desktop session
  for headed Chromium.
- Phone: whether Vanadium exposes the DevTools socket; the manual fallback
  stands if not.
- Capability-gated surfaces (Watchtower, Sequences, FULLGL) must be enabled in
  the fresh database or they are reported as blocked, not covered.
